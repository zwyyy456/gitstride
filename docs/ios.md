# GitStride iOS 开发与使用

GitStride 的移动端是 iPhone / iPad 原生客户端，最低支持 iOS / iPadOS 17。它与 macOS 版本共用项目数据、GitHub 操作和自动化服务源码，使用独立移动端页面。

## 构建

在 `GitStride.xcodeproj` 中选择 `GitStrideAppStore` scheme，然后选择 iPhone 或 iPad 运行设备；同一 scheme 选择 My Mac 时构建原生 macOS 版本。

```bash
xcodebuild -project GitStride.xcodeproj -scheme GitStrideAppStore \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
```

模拟器编译使用 `-destination 'generic/platform=iOS Simulator'`。真机运行需要在 Signing & Capabilities 中选择自己的开发团队，并确认 Bundle ID 的签名配置。

`GITSTRIDE_OAUTH_CLIENT_ID` 使用现有公开 OAuth App ID；自行分发时配置自己的 Client ID 并启用 Device Flow。自动化地址使用 `GITSTRIDE_AUTOMATION_BASE_URL`。客户端不需要 Client Secret，不包含 CLI 或 Sparkle。

## 使用入口

iPhone 底部入口按顺序为 **我的工作 → 项目 → 关注 → 设置**，各 Tab 保留自己的导航层级。

iPad 使用统一侧栏与右侧工作区，侧栏按所有者、项目、我的工作分类、关注项目分类和设置组织，与 macOS 的内容层级一致。宽窗口并排显示侧栏和内容，窄窗口由系统折叠为单列导航；旋转或调整窗口大小不切换导航容器。选择项目或工作分类后，条目详情在右侧工作区内进入，侧栏保持可达。各窗口独立保存当前导航选择。

- **我的工作**：自动查询分配给我的 Issue、我的 PR、待我 Review，导航标题显示当前范围；iPhone 在右上角筛选菜单切换范围与 PR 状态并记住上次选择，iPad 从侧栏切换范围，工具栏提供刷新与 PR 状态筛选。无需先关注项目。支持搜索和 PR 状态筛选。
- **项目**：按所有者浏览完整项目目录，iPhone 从导航栏菜单、iPad 从侧栏切换个人账号或组织；不再单独重复列出关注项目，目录中的星标表示关注状态；支持搜索、创建和关注。iPhone 逐层进入项目，iPad 从统一侧栏选择项目。不同窗口可独立选择所有者与项目，项目数据在窗口间共享。
- **关注**：汇总关注项目中的条目，默认显示未完成条目并按项目分组；搜索位于导航栏下方，更多菜单提供项目分组、选择条目与浏览项目；iPhone 在菜单切换范围，iPad 从侧栏选择关注分类。仅启用搜索或额外筛选时显示简短提示及清除入口，选择模式提供批量状态修改和归档。项目分组使用紧凑标题，条目 Status 与仓库信息对齐显示。未关注项目时显示完整空状态和浏览项目按钮，加载、失败与无匹配结果分别呈现。
- **设置**：首页显示账号和自动化摘要，分别进入 GitHub 账号、自动化、关于页面。

项目默认使用按 Status 分组的列表，分组沿用项目的状态名称、颜色和顺序，使用紧凑的普通标题；条目图标单独表示 Issue / PR 的状态。iPhone 和紧凑工作区将保存视图、筛选、分组和显示字段放在更多菜单中；iPad 工作区足够宽且未使用辅助功能大字号时，工具栏直接提供刷新、布局、筛选、显示配置和新增，更多菜单保留保存视图与项目管理操作；仅选中保存视图或启用筛选时显示简短提示及清除入口。iPhone 使用列表；iPad 工作区宽度达到 680 pt 时可选择看板，窄窗口自动使用列表，但保留已选择的布局偏好。筛选使用弹窗；管理项目逐层进入；新增 Issue、草稿、添加已有条目使用弹窗。搜索和筛选在布局之间保留。保存视图、字段显示和关注偏好保存在本机，不同步到其他设备，也不修改 GitHub 的保存视图。

从我的工作或项目列表点击条目，在 iPhone 当前 Tab 或 iPad 右侧工作区内进入原生详情，连续阅读标题和 Markdown 正文，并可继续进入关联 Issue。属性由详情工具栏打开：iPhone 和紧凑窗口使用可展开的 sheet，iPad 宽窗口使用侧边 inspector；多个已加载项目的属性在面板内切换。标题与正文编辑使用弹窗；更多操作提供编辑、分享、刷新和在 GitHub 打开。项目中的条目还支持归档，以及状态、日期、迭代、指派人、标签、里程碑和关系编辑。个人条目只有在已加载项目中存在真实 membership 时才提供该项目的属性编辑；否则属性面板展示已读取的基本信息。

创建 Issue 时，若项目有状态选项则必须选择；存在 Todo 时默认选中，与 macOS 一致。新增始终绑定打开表单时的项目，切换 Tab 不改变目标项目。提交后的进度与失败重试显示在待同步更改中；个人条目的编辑进度与重试显示在详情页。

按里程碑或父议题筛选时显示交付统计。统计覆盖当前项目该交付范围内的 Issue，不受其他筛选或隐藏看板列影响。

进入项目时自动加载目标项目，分别展示加载、错误、真实空项目和筛选无结果。我的工作使用紧凑标题与普通列表；搜索框直接显示在导航栏下、列表上方，不再常驻显示分类 segment 或项目控制栏。条目的标题、仓库、assignee 和状态标签共用内容列，分隔线与内容列对齐。项目目录复用 macOS 的稳定彩色图标。

## 自动化与刷新

自动化继续由现有 Worker 执行。客户端前台接收 WebSocket 事件并刷新；进入后台停止事件连接，回到前台重连并刷新。设置中的授权、恢复已有连接、暂停、恢复及删除操作复用现有服务。

本版不提供项目系统提醒，不请求通知权限，也不启动 My Work 轮询监控。

## 当前范围

已接入列表和详情编辑，iPad 宽窗口另提供看板；完整多列表格与 Roadmap 时间轴尚未迁移，日期与迭代仍可在详情中编辑。缓存用于启动展示和只读回退；待同步操作沿用现有内存状态，不提供离线写入或跨应用重启恢复。

## 运行与发布确认

编译不替代真实账号和设备验证。使用专用 GitHub 测试项目确认登录、浏览、创建编辑、批量操作与自动化；界面调整依据运行截图确认。普通开发不运行 UI 测试。

TestFlight 分发还需要开发者签名、App Store Connect 中的 iOS 平台配置、相应的隐私与商店资料，以及在 Xcode Organizer 中验证 Archive。源码中的构建配置不代表已完成上传或商店审核。
